Studi Kasus & Klasifikasi Siklus Transaksi BMT
⏱ ~12 menit

Kasus: BMT Berkah Mandiri adalah Lembaga Keuangan Mikro Syariah yang melayani 2.500 pedagang pasar tradisional. Setiap hari terjadi ratusan peristiwa bisnis (business events). Tugas pertamamu adalah mengelompokkan peristiwa tersebut ke dalam siklus transaksi yang tepat.

Tabel Pemetaan Peristiwa Bisnis BMT

NoPeristiwa Bisnis (Business Event)Pihak TerkaitSiklus Transaksi AISPertukaran Nilai Ekonomi
1Anggota menyetor tabungan harian Wadiah via tellerAnggota PenabungSiklus Pendanaan (Financing)Terima Kas → Catat Kewajiban Simpanan
2BMT membeli sepeda motor dari dealer untuk diserahkan ke nasabah murabahahDealer Motor (Vendor)Siklus Pengeluaran (Expenditure)Keluar Kas → Terima Persediaan Murabahah
3Nasabah membayar angsuran bulanan pembiayaan murabahah (pokok + margin)Nasabah PembiayaanSiklus Pendapatan (Revenue)Terima Kas → Kurangi Piutang & Akui Margin
4BMT membayar gaji bulanan (ujrah) staf collection dan tellerKaryawanSiklus Penggajian / SDM (Payroll)Keluar Kas → Terima Jasa Tenaga Kerja
5BMT menghitung dan mendistribusikan bagi hasil bulanan kepada pemilik depositoInvestor MudharabahSiklus Pendanaan (Financing)Keluar Kas / Tambah Saldo → Beban Bagi Hasil
6BMT menyusun neraca saldo dan laporan sumber penyaluran dana ZISPengurus & DPSSiklus Buku Besar (GLARS)Integrasi Data → Laporan Keuangan
💡 Prinsip Syariah: Setiap siklus transaksi harus mengaitkan Akad Syariah yang mendasarinya (Wadiah, Murabahah, Mudharabah, Ijarah al-Amal). Kesalahan penempatan akad menyebabkan cacat syariah (non-halal income).

Perancangan Dokumen Sumber & Pengendalian Input
⏱ ~12 menit

Data yang masuk ke dalam AIS harus divalidasi sejak awal melalui Dokumen Sumber (Source Documents) berotorisasi dan mekanisme otomasi input (Source Data Automation).

Contoh Desain Formulir Aplikasi Pembiayaan Murabahah (Digital Form)

STRUKTUR FIELD FORMULIR APLIKASI PEMBIAYAAN (DIGITAL SOURCE DOCUMENT)
[HEADER DOKUMEN] Nomor Aplikasi : AP-MRB-2026-XXXX (Pre-numbered Sequence Code) Tanggal Input : [Automated Timestamp] Cabang/Unit : BMT Berkah Mandiri Unit Pasar Anyar [DATA ANGGOTA] Nomor Anggota : [CUST-ID / Scan E-KTP Reader] (Source Data Automation) Nama Lengkap : Siti Maryam No. WhatsApp : 0812-XXXX-XXXX Pekerjaan : Pedagang Sembako [DETAIL AKAD MURABAHAH] Nama Barang : Kulkas Showcase 2 Pintu Merk X Harga Beli BMT : Rp 4.500.000 (Sesuai Faktur Dealer) Margin BMT : Rp 900.000 (Transparan / Disepakati) Harga Jual BMT : Rp 5.400.000 (Harga Beli + Margin) Jangka Waktu : 12 Bulan (Angsuran Rp 450.000/bulan) [KONTROL & OTORISASI] Tanda Tangan Digital Nasabah : [E-Signature] Rekomendasi Account Officer : [Disetujui / Catatan Kelayakan] Otorisasi Manajer Pembiayaan : [Digital PIN Approval]
⚠️ Pengendalian Input Wajib (Input Controls):
  • Pre-numbered sequence: Formulir bernomor urut otomatis tercetak dari sistem untuk mencegah dokumen hilang atau transaksi fiktif.
  • Turnaround document QRIS: Setiap nasabah pembiayaan diberikan kartu angsuran ber-barcode/QRIS yang di-scan langsung saat bayar, sehingga teller tidak perlu mengetik nomor anggota secara manual.
3
Perancangan Bagan Akun (Chart of Accounts - COA) LKS
⏱ ~15 menit

Buka file dataset-coa-bmt-p02.csv yang sudah disediakan di folder ini menggunakan Microsoft Excel, Google Sheets, atau LibreOffice Calc. BMT Berkah Mandiri menggunakan struktur Group Coding 5-Digit:

Format 5 Digit: [D1: Kategori Utama] - [D2: Sub-Kategori] - [D3: Kelompok Akun] - [D4-5: Nomor Spesifik]
Contoh 11301: 1=Aset → 1=Aset Lancar → 3=Piutang → 01=Murabahah.

Langkah Analisis Dataset COA

ANALISIS SPREADSHEET — dataset-coa-bmt-p02.csv (33 baris, 6 kolom)
Kolom: Kode_Akun | Nama_Akun | Kategori_Akun | Tipe_Akun | Saldo_Normal | Akad_Syariah LANGKAH 1 — Filter Kategori Aset: Excel: Data → Filter → Kategori_Akun = "Aset Lancar" Pertanyaan: Berapa akun Aset Lancar yang ada? LANGKAH 2 — COUNTIF per Akad: =COUNTIF(F:F, "Murabahah") → Berapa akun terkait Murabahah? =COUNTIF(F:F, "Mudharabah") → Berapa akun terkait Mudharabah? =COUNTIF(F:F, "N/A") → Berapa akun tidak berbasis akad? LANGKAH 3 — Identifikasi Contra Account: Filter: Tipe_Akun = "Contra Account" Temukan: Kode dan nama akun kontra (pengurang) LANGKAH 4 — Cek Logika Saldo Normal: Aset dan Beban → saldo normal = Debit Kewajiban, Ekuitas, Pendapatan → saldo normal = Kredit Apakah semua baris dataset sudah konsisten?

Pemetaan Hierarki Data & Master vs Transaction File
⏱ ~12 menit

Di dalam sistem basis data relasional AIS BMT, data dipisahkan menjadi Master File (permanen) dan Transaction File (harian/berkala).

Desain Skema Tabel Database BMT

Nama TabelTipe FilePrimary Key (PK)Foreign Key (FK)Contoh Field / Atribut
Tabel_Master_Anggota Master File no_anggota - nama_lengkap, alamat, no_ktp, no_wa, tgl_daftar, status_keanggotaan
Tabel_Master_Rekening_Simpanan Master File no_rekening no_anggota jenis_akad (Wadiah/Mudharabah), saldo_terkini, tgl_buka, status_aktif
Tabel_Master_Akun_COA Master File kode_akun - nama_akun, kategori, saldo_normal, saldo_berjalan
Tabel_Transaksi_Kas_Harian Transaction File id_transaksi no_rekening, kode_akun tgl_transaksi, jenis_transaksi (Setor/Tarik), jumlah_rp, id_teller, timestamp
Tabel_Transaksi_Angsuran_Murabahah Transaction File id_angsuran no_akad_pembiayaan angsuran_ke, tgl_bayar, porsi_pokok, porsi_margin, denda_kebajikan
💡 Mekanisme Update: Ketika nasabah menyetor Rp 500.000, transaksi dicatat di Tabel_Transaksi_Kas_Harian (Transaction File), dan secara otomatis sistem memperbarui saldo_terkini di Tabel_Master_Rekening_Simpanan serta saldo_berjalan di Tabel_Master_Akun_COA (Master File).

Tantangan Mandiri & Audit Jejak Transaksi
⏱ ~12 menit

Kerjakan 3 tugas analisis mandiri berikut sebagai bukti pemahaman praktis proses bisnis dan data dalam AIS.

🎯 3 Tugas Tantangan Analisis Kasus

Tantangan 1 — Rekonsiliasi Control Account vs Buku Pembantu: Pada akhir bulan, saldo Akun Kontrol 11301 Piutang Murabahah di Buku Besar tercatat Rp 1.250.000.000. Namun saat dijumlahkan seluruh rincian kartu piutang di Buku Pembantu (Subsidiary Ledger), totalnya hanya Rp 1.235.000.000 (ada selisih Rp 15.000.000). Apa saja kemungkinan penyebab kesalahan sistemik ini, dan dokumen sumber apa yang harus diperiksa untuk melakukan penelusuran jejak audit (audit trail)?
Tantangan 2 — Perancangan Struktur Akun Baru (COA Extension): BMT Berkah Mandiri berencana meluncurkan produk baru: "Pembiayaan Konstruksi Istishna" dan "Tabungan Qurban Mudharabah". Rancanglah kode akun 5-digit yang tepat untuk kedua produk tersebut beserta kategori neraca dan saldo normalnya!
Tantangan 3 — Evaluasi Kontrol Anti-Fraud: Seorang staf penagih lapangan (mobile collector) menerima setoran angsuran tunai Rp 1.000.000 dari anggota pedagang pasar, namun tidak langsung menginputnya ke sistem melainkan baru disetor 3 hari kemudian (lapping fraud). Rancanglah 2 pengendalian input / teknologi otomasi yang dapat mencegah kecurangan penundaan setoran tersebut!
