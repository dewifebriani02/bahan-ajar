Tujuan Pembelajaran & Peta Konsep
CPMK-2

Sejak P01–P03 kita membahas teori di balik visualisasi yang baik: memilih chart yang tepat, prinsip Gestalt, dan menghindari manipulasi data. Sekarang saatnya Ilmu & Amal — kita akan membuka Power BI Desktop untuk pertama kalinya dan benar-benar membangun laporan.

💡 Mengapa Power BI? Power BI adalah tool BI enterprise paling banyak dipakai di industri (Gartner Magic Quadrant Leader 6 tahun berturut-turut), gratis untuk versi Desktop, dan terintegrasi penuh dengan ekosistem Microsoft (Excel, Azure, Teams) yang umum dipakai lembaga keuangan syariah di Indonesia.

Setelah pertemuan ini kamu mampu...

  • 1. Navigasi Interface: Membedakan fungsi 3 tampilan utama Power BI Desktop — Report View, Data View, dan Model View.
  • 2. Menghubungkan Sumber Data: Mengimpor data dari Excel, CSV, dan sumber Web ke dalam Power BI.
  • 3. Memodelkan Data: Membedakan Fact Table dan Dimension Table, serta membangun relationship antar tabel.
  • 4. Membuat Visual Dasar: Menggunakan visual bawaan — Bar, Line, Pie, Card, Table, dan Matrix — sesuai konteks data.
  • 5. Publikasi Laporan: Mem-publish report ke Power BI Service dan memahami akses via Power BI Mobile.

02
Koneksi Sumber Data — Get Data
CPMK-2

Langkah pertama membangun laporan apa pun adalah menghubungkan Power BI ke sumber data. Tombol Get Data di Home Ribbon adalah gerbang masuk semua data ke Power BI — mendukung lebih dari 100 jenis konektor, dari file lokal hingga cloud database enterprise.

Sumber DataKapan DipakaiCatatan Penting
Excel WorkbookData operasional harian yang masih dikelola manual (laporan cabang, rekap kasir)Pilih sheet/table spesifik, bukan seluruh workbook
Text/CSVEkspor data dari sistem lain (SIA, aplikasi core banking, hasil query)Periksa delimiter dan encoding (UTF-8) agar karakter tidak rusak
WebData publik (kurs, indeks, data BPS) yang diperbarui berkala dari halaman/API webGunakan Refresh terjadwal agar data tidak basi
SQL Server / DatabaseData transaksional skala besar milik perusahaan (akan dibahas di Fase 3)Pilih mode Import vs DirectQuery sesuai volume data

📋 Alur Umum Import Data ke Power BI Desktop

  1. 1Klik Get Data di Home Ribbon ➔ pilih jenis sumber (misal Text/CSV).
  2. 2Arahkan ke lokasi file, lalu klik Open. Power BI menampilkan jendela preview data.
  3. 3Klik Transform Data untuk membuka Power Query Editor dan memeriksa/membersihkan tipe data sebelum dimuat.
  4. 4Klik Close & Apply — data resmi masuk ke dalam model Power BI kamu.
⚠️ Kebiasaan Baik: Selalu klik Transform Data dulu sebelum Load langsung. Memeriksa tipe data di awal (apakah kolom tanggal terbaca sebagai teks, apakah kolom nominal terbaca sebagai angka) mencegah error yang jauh lebih sulit dilacak setelah model dan visual sudah dibangun.
03
Model Data Dasar: Fact Table, Dimension Table & Relationship
CPMK-2

Ini adalah konsep paling penting di pertemuan ini. Data bisnis yang baik jarang disimpan dalam satu tabel raksasa — melainkan dipecah menjadi beberapa tabel yang saling terhubung, mengikuti pola Fact Table dan Dimension Table.

Jenis TabelIsiCiri Khas
Fact TablePeristiwa/transaksi yang terjadi berulang — angka yang bisa dijumlah (nominal, margin, kuantitas)Baris sangat banyak, sebagian besar kolom berisi angka dan kunci asing (foreign key) ke tabel dimensi
Dimension TableKonteks/atribut deskriptif — nama cabang, kategori produk, kotaBaris relatif sedikit, kolom deskriptif (teks), punya satu kunci utama (primary key)

Pola ini disebut Star Schema — satu tabel fakta di tengah, dikelilingi beberapa tabel dimensi. Bentuk paling umum dan direkomendasikan dalam pemodelan Power BI.

📋 Cara Membangun Relationship di Model View

  1. 1Buka tab Model View (ikon diagram di panel kiri).
  2. 2Klik dan tahan kolom cabang_id pada tabel dim_cabang, lalu seret (drag) ke kolom cabang_id pada tabel fact_pembiayaan.
  3. 3Power BI otomatis membuat garis relationship dengan kardinalitas 1-ke-Banyak (1:*) — satu cabang punya banyak transaksi.
  4. 4Ulangi untuk menghubungkan produk_id pada dim_produk ke fact_pembiayaan.
⚠️ Kesalahan Pemula Paling Umum: Menggabungkan semua data ke dalam satu tabel raksasa ("flat table") dengan nama cabang dan nama produk diulang-ulang di setiap baris transaksi. Ini membuat file besar, lambat, sulit dikelola, dan rawan inkonsistensi penulisan (contoh: "Jakarta Pusat" vs "JAKARTA PUSAT" dianggap dua nilai berbeda). Star schema menyelesaikan masalah ini dengan menyimpan nama cabang hanya sekali di dimension table.
04
Visual Bawaan Power BI — Bar, Line, Pie, Card, Table, Matrix
CPMK-2

Setelah model data siap (Fact + Dimension terhubung), kita mulai membangun visual di Report View. Panel Visualizations menyediakan puluhan jenis chart bawaan — berikut 6 yang paling sering dipakai untuk laporan bisnis pemula.

📊
Bar / Column Chart
Membandingkan nilai antar kategori (per cabang, per akad)
📈
Line Chart
Menampilkan tren nilai sepanjang waktu (per bulan)
🥧
Pie Chart
Komposisi sederhana, maksimal 3–5 kategori (ingat jebakan P03!)
🔢
Card
Menonjolkan satu angka KPI utama (Total Pembiayaan)
📋
Table
Rincian data mentah per baris, perlu presisi angka detail
▦
Matrix
Tabel pivot interaktif — baris x kolom x nilai, bisa expand/collapse

Cara Kerja Umum Membuat Visual

📋 Pola Universal Membuat Visual Apa Pun

  1. 1Klik ikon jenis visual yang diinginkan di panel Visualizations — sebuah placeholder kosong muncul di canvas.
  2. 2Dari panel Fields, drag kolom dimensi (misal nama_cabang) ke drop-zone Axis atau Legend.
  3. 3Drag kolom numerik fact table (misal nominal_pembiayaan) ke drop-zone Values — Power BI otomatis menjumlahkannya (Sum).
  4. 4Gunakan tab Format (ikon kuas) untuk menyesuaikan warna, judul, dan data label sesuai prinsip Gestalt yang sudah dipelajari di P02.
💡 Koneksi ke Materi Sebelumnya: Prinsip pemilihan chart di P02 (Chart Chooser Framework) dan menghindari jebakan visual di P03 (Lie Factor, 3D distortion) tetap berlaku penuh saat kamu memilih visual di Power BI. Tool hanya alat — kaidah desainnya tetap sama.
05
Publikasi ke Power BI Service & Power BI Mobile
CPMK-2

Laporan yang hanya tersimpan di laptop pribadi (file .pbix) belum bisa dilihat oleh direksi atau tim lain. Power BI Service (aplikasi web di app.powerbi.com) adalah tempat laporan dipublikasikan, dibagikan, dan diatur jadwal refresh otomatisnya.

📋 Langkah Publish ke Power BI Service

  1. 1Di Power BI Desktop, klik Publish pada Home Ribbon.
  2. 2Masuk (sign in) dengan akun Microsoft/organisasi, lalu pilih Workspace tujuan (misal "My Workspace" untuk latihan pribadi).
  3. 3Setelah proses upload selesai, klik link yang muncul untuk membuka laporan langsung di browser Power BI Service.
  4. 4Atur Scheduled Refresh (opsional) agar data di Service otomatis diperbarui dari sumbernya secara berkala.
AspekPower BI DesktopPower BI Service
PlatformAplikasi Windows (install lokal)Aplikasi web (app.powerbi.com)
Fungsi UtamaMembangun & mendesain laporanMembagikan, memantau, menjadwalkan refresh
KolaborasiSatu pengguna, satu fileBanyak pengguna via Workspace bersama
Akses MobileTidak tersediaTersedia via Power BI Mobile (iOS/Android)
📱 Power BI Mobile: Setelah dipublikasikan ke Service, laporan otomatis dapat diakses lewat aplikasi Power BI Mobile — memungkinkan pimpinan lembaga keuangan syariah memantau KPI pembiayaan kapan saja tanpa membuka laptop, lengkap dengan notifikasi data alert jika metrik melewati ambang batas tertentu.

☽ Nilai Utama: Ilmu & Amal (Pengetahuan yang Diimplementasikan)
Islam menempatkan tingginya derajat orang berilmu — namun ilmu yang bernilai adalah ilmu yang diamalkan, bukan sekadar disimpan sebagai teori.

Rasulullah ﷺ bersabda:

« فَضْلُ الْعَالِمِ عَلَى الْعَابِدِ كَفَضْلِ الْقَمَرِ عَلَى سَائِرِ الْكَوَاكِبِ »
"Keutamaan orang berilmu atas ahli ibadah (yang beribadah tanpa ilmu) seperti keutamaan bulan atas bintang-bintang." (HR. Abu Dawud & Tirmidzi)

Pertemuan ini adalah amal pertama dari ilmu BI yang sudah kamu pelajari sejak P01. Tiga pertemuan sebelumnya membekalimu dengan konsep — Chart Chooser, Gestalt, Anti-Tadlis. Hari ini, konsep itu diwujudkan menjadi laporan nyata yang bisa dipakai orang lain untuk mengambil keputusan.

Refleksi: Amanah dalam Membangun Model Data

  • Relationship yang Benar adalah Amanah: Menghubungkan fact table ke dimension table yang salah (misal cabang_id tertukar) akan menghasilkan laporan yang secara teknis "jalan" tapi angkanya keliru — sebuah bentuk kelalaian yang bisa menyesatkan pengambil keputusan tanpa disadari.
  • Sumber Data yang Sah: Ilmu koneksi data (Get Data) harus dipakai untuk menghubungkan sumber yang sah dan berizin — bukan untuk mengakses data pihak lain tanpa hak.
  • Publikasi sebagai Tanggung Jawab: Begitu laporan dipublikasikan ke Power BI Service dan bisa diakses banyak orang, tanggung jawab (amanah) atas akurasi angka yang ditampilkan menjadi lebih besar — inilah makna nyata dari "ilmu yang diamalkan."
